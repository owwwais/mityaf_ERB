# مطياف ERP

نظام إدارة موارد شركة مطياف: المالية، التسعير، المشاريع والعملاء في مكان واحد.
عربي بالكامل (RTL)، يعمل على الجوال، وبهوية [mityaf.com](https://mityaf.com) البصرية.

## التشغيل

```bash
npm install
```

```bash
npm run dev
```

افتح <http://localhost:3000>. أول زيارة تفتح صفحة الإعداد: اسمك، اسم شريكك، بريدك وكلمة المرور.
يمكنك تحميل بيانات تجريبية للاستكشاف ثم حذفها من **الإعدادات ← تصفير البيانات**.

لا يحتاج التشغيل المحلي قاعدة بيانات خارجية: يعمل على Postgres مضمَّن (PGlite) يحفظ بياناته في مجلد `.data/`.

## الوحدات

| الوحدة | ما تفعله |
|---|---|

| **المصروفات** | سجل المصروفات (من دفع، على أي مشروع، أي فئة) والتكاليف المتكررة مع تسجيلها بضغطة. |

## كيف يُحسب السعر

المحرك في `src/modules/pricing/engine.ts`، منطق خالص مغطى بالاختبارات، ويعمل في المتصفح (معاينة حيّة) وعلى الخادم (عند الحفظ).

1. **الساعات القابلة للفوترة سنوياً** = ساعات الشركاء الأسبوعية × أسابيع العمل × نسبة القابل للفوترة.
2. **تكلفة الساعة المبيعة** = (سعر وقت الشريك الحقيقي ÷ نسبة القابل للفوترة) + (التكاليف التشغيلية السنوية ÷ الساعات القابلة للفوترة).
3. **تكلفة المشروع** = ساعاته × (1 + هامش المخاطرة) × تكلفة الساعة + تكاليفه المباشرة.
4. **السعر** = التكلفة ÷ (1 − هامش الربح)، ثم علاوة الاستعجال وضغط العمل، ثم قيمة المنتج الجاهز، ثم الخصم.

الحاسبة تعرض مع السعر: الهامش الفعلي، مقارنة بقاعدة «فتح العداد + سعر الساعة»، سلّم أسعار (اقتصادي، موصى به، مميّز)،
توزيع المبلغ على الخزينة والشركاء، وعائد الساعة الفعلي. وتحذّر إن نزل السعر تحت التكلفة أو تحت الحد الأدنى للهامش.

**التكاليف التشغيلية السنوية** تأتي من «المصروفات ← التكاليف المتكررة». أدخلها أولاً، فبدونها يفترض التسعير أن تشغيل الشركة مجاني.

## توزيع العوائد والتسوية

يُطبَّق على صافي كل مشروع (المحصَّل − تكاليفه المباشرة)، والنسب تُعدَّل من الإعدادات:

- **مشروع مشترك:** 20٪ للخزينة، والباقي بحصص الشركاء.
- **مشروع فردي:** 20٪ لجالب المشروع، 60٪ للمنفّذ، 20٪ للشركة.

ولأن التحصيل والصرف يمرّان بحسابات شخصية، تفصل صفحة «الشركاء والخزينة» بين **ما بحوزة** كل طرف و**ما يستحقه**،
وتقترح أقل عدد من التحويلات لتصفير الفرق. المنطق في `src/modules/finance/settlement.ts`.

## قاعدة البيانات والنشر

النظام يعمل على أي Postgres. ضع رابط القاعدة في `DATABASE_URL` والجداول تُنشأ تلقائياً عند أول تشغيل.

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | رابط Postgres. فارغ = القاعدة المضمَّنة المحلية. |
| `AUTH_SECRET` | مفتاح توقيع الجلسات، **مطلوب في الإنتاج**. يُولَّد بـ `openssl rand -base64 32`. |
| `MITYAF_AUTO_MIGRATE` | ضعه `0` لإيقاف الترحيل التلقائي وإدارته يدوياً بـ `npm run db:migrate`. |

**Neon:** أنشئ مشروعاً وانسخ رابط الاتصال الذي يحوي `-pooler`.
**Supabase:** من Project Settings ← Database انسخ رابط Transaction pooler (المنفذ 6543).

**النشر على Vercel:** اربط المستودع، أضف `DATABASE_URL` و`AUTH_SECRET` في Environment Variables، وانشر.
القاعدة المضمَّنة لا تصلح على Vercel لأن نظام الملفات هناك مؤقت.

## بنية المشروع

```
src/
  app/                صفحات Next.js (App Router)
    (auth)/           الدخول والإعداد الأولي
    (app)/            صفحات النظام داخل القالب
    quote/[id]/       نسخة العميل من عرض السعر
  components/         مكوّنات الواجهة المشتركة (نماذج، نوافذ، رسوم، قالب)
  db/                 الاتصال بالقاعدة وتجميع المخططات
  lib/                المصادقة، التنسيق، التحقق من المدخلات
  modules/            وحدة لكل مجال: schema / queries / actions / components
    registry.ts       سجل الوحدات: مصدر التنقل الوحيد
drizzle/              ملفات الترحيل (تُولَّد، لا تُكتب يدوياً)
public/brand, fonts   شعار وخطوط الهوية
```

### إضافة وحدة جديدة

1. أنشئ `src/modules/<name>/schema.ts` وأعد تصديره من `src/db/schema.ts`.
2. ولّد الترحيل: `npm run db:generate`.
3. اكتب `queries.ts` و`actions.ts` (كل دالة تبدأ بـ `requireUser()`).
4. أضف الصفحات تحت `src/app/(app)/<name>/`.
5. أضف سطراً في `src/modules/registry.ts` لتظهر في القائمة.

## الهوية البصرية

الألوان والزوايا والخطوط والشعار مأخوذة من mityaf.com: خط «تجارب» للعربية و«ثمانية» للاتينية والأرقام و Plex Mono
للتسميات التقنية. الرموز في `src/app/globals.css`، والملفات في `public/fonts` و`public/brand`.
ملفات الخطوط منسوخة من موقع الشركة؛ إن كان المستودع عاماً فتأكدوا أن رخصة الخطوط تسمح بإعادة نشرها.

## حدود النسخة الحالية

- المحاسبة على أساس نقدي؛ لا فواتير ضريبية ولا قيود مزدوجة.
- عملة واحدة.
- لا مرفقات (صور الإيصالات) ولا إشعارات بريدية.
- العملاء يُدخلون يدوياً؛ لا مزامنة مع Notion بعد.
